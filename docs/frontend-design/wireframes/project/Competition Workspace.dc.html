3 · Workspace navigation

Tabs: Overview · Fixtures · Table · Performance. Performance is justified now that three payloads back it (observations, temporal-performance, position-trajectory). Inside it, a 3-way switch: Season · Last 5 vs previous 5 · Positions. Goals, Teams, Players and Venues still have no dedicated payload, so they get no tabs.

Method disclosure: the trajectory is a reconstruction from results (points → goal difference → goals for), not the official order. The panel says so in plain words, including that early ties can be arbitrary. Because of that, reconstructed positions (through 7 Sep) can differ from the official table (as of 11 Aug); the grid shows both orders explicitly.

No rankings or "best/worst" labels. "Direction" describes the change, not quality. Provider and provenance fields are never shown.

5 · Fixtures tab (edition-first)

  • Filter: Results · Scheduled · Postponed (radiogroup). No counts, to avoid client-side calculation.
  • Grouped by kickoff date (UTC, same as Phase C). There is no round field, so no matchday grouping.
  • Results newest first (5–7 Sep shown), then "Load earlier results". Scheduled in kickoff order. Postponed at their original kickoff.
  • Status is shown as supplied. Some SCHEDULED kickoffs (30 Aug) are earlier than later results. The UI doesn't relabel them.
  • Rows are identical to Phase C, and each row links to the Match workspace (F).

6 · Table tab

  • Header: Standings · "Overall" static chip (only TOTAL exists; becomes a selector if HOME/AWAY appear) · As of 11 Aug 2026.
  • Columns # · Team · P · W · D · L · GF · GA · GD · Pts · Gap, each with a title attribute giving its full name. Gap = table-context.teams[].adjacent.above.pointsGap (points behind the team directly above; — for 1st; mobile shows it in the row expansion). change is null in the payload, so no movement arrows. Numbers are mono and tabular, right-aligned; Pts bold; GD signed (+/−/0) with --edge/--risk/--faint as a secondary cue.
  • Rows: thin separators + subtle zebra (raised 30%, as specified here) + hover --raised. The team name is a --cool link → Team workspace (E).
  • No zones, form or streaks. Footer note: "Results after 11 Aug aren't reflected in this table yet." (asOf is older than the latest result, 7 Sep.)

7–8 · Context and trajectory

All four endpoints are now used: observations (Overview "Season so far" and Performance · Season), temporal-performance (Overview rail and Performance · Last 5 vs previous 5), table-context (Table · Gap column), and position-trajectory (Performance · Positions). Every chart carries a text alternative (aria-label with the values) and, where it helps, a data-table toggle.

15 · Accessibility

  • h1 competition → h2 panels → h3 date groups. Tabs use role=tab with aria-selected; filters use a radiogroup.
  • Standings use role="table" with column headers carrying full-name titles, and the aria-label states "overall, as of 11 August 2026". A mobile expand toggle belongs to each row.
  • GD is always signed; status chips are words + glyphs; the season selector's aria-label says only one season is available.
  • Section errors use role="alert"; loading uses aria-busy plus a status message.
