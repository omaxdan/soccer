4 · Information hierarchy

  1. Hero: H1, one paragraph, two CTAs, and an "On this page" index of the seven capabilities (this replaces the Landing preview, so the two heroes differ).
  2. Framework: six questions in order, with an Evidence bar under all of them.
  3. Capabilities 01–06 follow the framework order. Statistical attributes is a supporting strip between History and Intelligence.
  4. Evidence: Observed → Derived → Context → Intelligence, each with a real example.
  5. Workflow: six steps from fixture list to intelligence, each mapped to where it lives in the product.
  6. Audience: four ruled use-case lines.
  7. Final CTA and Footer (Features marked current).

10 · Reusable components (new for B2)

  • PageIndex: a numbered in-page nav panel. Reusable on long public pages (Pricing FAQ, Legal).
  • FrameworkDiagram: numbered question steps with an evidence bar.
  • FeatureSection: eyebrow number · H2 · copy · optional fragment, in split A, split B or paired variants.
  • ProductFragment: a figure with a panel and a figcaption stating data source and date.
  • OutcomeBar: W/D/L stacked bar that always sits over W n · D n · L n · n text.
  • EvidenceLadder: four ruled cells with a kind label, explanation and a mono example.
  • WorkflowList: numbered steps with a "where in product" column.

Reused from A/B1: AppHeader (anon), CTAButton, WorkspaceTabs vocabulary, FormBadge, StatusChip, selector chip, DataTable group header, final CTA band, PublicFooter.

11 · Token usage

  • Surfaces alternate canvas → --panel band (framework) → canvas (01–05) → --raised band (intelligence) → canvas (evidence) → --panel band (workflow) → canvas → --panel (CTA).
  • --amber: primary CTAs, active date chip, "06 · INTELLIGENCE" label, final framework step. --amber-dim edges mark the intelligence band and final steps.
  • --edge / --muted / --risk appear only as W/D/L and SUPPORTS/NEUTRAL/CONTRADICTS inside fragments. --cool: SCHEDULED chip and the EVIDENCE bar label. --warn is unused.

12 · Responsive behavior

  • Desktop: hero 7/5 with index; framework 6-across with →; splits alternate 5/7 ↔ 7/5; readiness and context paired; evidence 4-across; workflow 4/8.
  • Tablet: hero and index stack; framework 3 × 2 with ↓; splits stack text first, fragment second; readiness and context stay paired; evidence 2 × 2; audience 2 columns.
  • Mobile: everything one column; the framework becomes a vertical list with ↓ (still six readable steps); fixture fragment trims to two rows per day; "where" labels move under each workflow step; CTAs full-width. Type stays at 13px or above.

13 · Accessibility

  • One h1; each capability is an h2 with aria-labelledby; framework steps, evidence cells and tiers use h3; the framework, evidence and workflow use ol; readiness uses dl.
  • The hero index is a nav labelled "On this page" with real anchors; focus follows the amber ring.
  • Every W/D/L badge has an aria-label; outcome bars always sit above the text counts; SUPPORTS/NEUTRAL/CONTRADICTS are words; FT/SCHEDULED chips carry text.
  • Missing travel shows — in --faint; the caption says why.
  • Fragments are figures with captions naming source and date; arrows are aria-hidden.
