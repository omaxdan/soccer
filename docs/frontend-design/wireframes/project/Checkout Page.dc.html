B6 · Checkout · spec

VERIFIED DESIGN SYSTEM · PROPOSED UX · PENDING commercial, payment or legal source needed

1–2 · Compositions

Desktop 1a: a 1008px workspace in a 7 / 5 split (the Phase A 7+5 primitive), with a sticky summary on the right. Tablet 1b keeps the split. Mobile 1c is one column: heading → plan → payment → billing-terms slot → summary with CTA last, so the amount and the action sit together at the end.

Shell

This is the AuthShell from B4/B5 with the right side swapped: "Signed in · email" instead of "Back to PitchTerminal", which confirms the account from B5 without showing any auth UI. Above the workspace are "← Change plan" (→ B3) and a 3-step progress list: Plan ✓ · Payment · Confirmation (= B7).

3 · Selected-plan context

Panel "1 · Your plan": plan name, LEVEL n, the same 4-segment depth meter and intent line as the Pricing cards, and a "Change" link. Only Pro and Elite reach checkout. There is no price here; the price lives only in the summary.

4 · Payment form

  • A provider-neutral slot: "Payment field A / B / C" in the standard FormField (44px, --raised, amber focus, reserved 18px error line). Label meta: "set by payment method".
  • When a provider is chosen, its fields replace A–C inside the same panel. Labels, formats, autocomplete tokens and how many fields there are all come from that integration PENDING.
  • No card-brand logos, provider names, wallets or security claims.
  • Below it, a dashed "Billing terms · PENDING" slot reserves space for the renewal, cancellation and payment disclosure and the Terms link (B8). No consent checkbox is invented.

11 · Responsive

  • Desktop 1008 max, 7/5, sticky summary at top 16.
  • Tablet: same split with 24px margins; the summary stays sticky.
  • Mobile: single column, summary static and last, CTA 48px full width, 12px margins. The progress list wraps under "Change plan". The header drops the "Signed in" label and keeps the email (truncated).

12 · Accessibility

  • h1 "Review and pay"; sections are labelled by h2 "1 · Your plan", "2 · Payment details", "3 · Order summary"; the summary is an aside with a dl.
  • Progress list: ol with aria-current="step" on the active step; ✓ and numbers as well as colour.
  • Every field has a visible label; errors are tied with aria-describedby.
  • Disabled CTA reason in text via aria-describedby. Processing and failure are announced (status / alert).
  • Tab order: Change plan → plan Change → fields → CTA → Change plan (secondary).
  • No colour-only meaning: TBD, Pending and "!" are all text.
