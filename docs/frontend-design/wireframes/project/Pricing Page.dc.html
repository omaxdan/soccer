B3 · Pricing · spec

VERIFIED established in project context · PROPOSED structure or copy · DECISION commercial call still open.

1 · Page structure

  1. Hero: H1, one sentence, BillingToggle slot (hidden until periods exist).
  2. Plan cards: Guest · Free · Pro · Elite.
  3. Comparison: capability matrix, 5 groups, all cells TBD.
  4. Levels explained: one ruled line per level.
  5. Commercial details: 5 policy slots.
  6. FAQ: 6 questions, answers pending.
  7. CTA, then the shared public footer.

2 · Plan-card system

  • All four cards use the same --panel surface, border and CTA (secondary button). No card is larger, brighter or badged.
  • Increasing depth is shown by a 4-segment depth meter (--muted fill on --line), plus "LEVEL n" text and aria-label "Access depth n of 4". It describes breadth, not quality.
  • Price block: the value slot reads "Price TBD" in --faint mono with "Billing period not yet specified". Guest reads "No account" because it is the anonymous state from Phase A, not a price.
  • Feature list mirrors the five matrix groups, each with a ◌ TBD chip, so card and matrix can't disagree.
  • Recommended treatment (reserved): if a plan is chosen, it gets a --amber-dim border, a "RECOMMENDED" label-cap chip in --amber, and the primary amber CTA; aria-describedby points at the label. Not applied, because no plan has been chosen.

3 · Comparison-matrix system

  • Border-separated DataTable pattern from Phase A: .panel wrapper, .label-cap head, --raised group bands, 1px row rules, hover --raised.
  • Built as role="table" / row / columnheader / rowheader / cell, so the collapsible groups work reliably; the accessible name states that all entitlements are to be confirmed.
  • Cell vocabulary: ✓ Included (--text) · — Not included (--faint) · ◌ TBD (dashed --faint). The legend sits above the table, and every symbol has a text label.
  • Groups collapse with a button (aria-expanded) in the band. Desktop starts with all groups open.

5 · Commercial placeholder strategy

  • One placeholder vocabulary everywhere: ◌ TBD (entitlements), Price TBD (money), ◌ PENDING · Not yet specified (policies), ◌ COMMERCIALLY PENDING (FAQ answers). All use the Phase A PENDING chip (dashed --faint).
  • BillingToggle is drawn dashed, disabled and labelled "Period A / Period B". In production it isn't rendered until at least two periods exist.
  • Replacing a placeholder with a real value needs no layout change: every slot is sized for a short value plus a one-line note.
  • No trial, discount, limit, refund, provider or urgency language appears anywhere.

7 · Responsive

  • Desktop: 4 cards across; full matrix (capability column 34%); explanations, details and FAQ in a 4/8 split.
  • Tablet: cards 2 × 2; full matrix still fits (min-width 680, scrolls inside its panel if narrower); splits stack.
  • Mobile: cards stack; the matrix is replaced by a PlanSelector (4-segment tab list, 44px) plus expandable CapabilityGroups for the selected level. No tiny 4-column table. CTAs are full-width.

8 · Accessibility

  • One h1; each section has an h2 (the plans h2 is visually hidden); card names and FAQ questions are h3.
  • Cards are list items in a ul. The depth meter is role="img" with a text label. CTAs are links because they navigate.
  • The matrix uses table roles with row and column headers; TBD cells have aria-label "To be confirmed".
  • Plan switcher: role="tablist", aria-selected, amber underline and weight change. Groups and FAQ rows are buttons with aria-expanded.
  • BillingToggle: role="radiogroup" with aria-disabled while pending.
  • A future recommended state would be announced by text, not only by the amber border.

9 · Component inventory

PricingHeader · BillingToggle · PlanCard · PlanPrice · DepthMeter (new) · PlanFeatureList · FeatureComparison · CapabilityGroup · PlanSelector · PolicyList (new) · FAQ · PricingCTA · PublicFooter. Reused from Phase A: AppHeader, CTAButton, DataTable, PENDING chip, final CTA band.

10 · Token usage

--panel cards, matrix, details band and CTA band · --raised group bands, selected tab, CTA fills · --line rules and meter track · --muted meter fill and labels · --faint every placeholder · --amber only for the primary "Explore fixtures" CTA and the selected mobile tab · --amber-dim for the CTA band rule. --edge, --warn, --risk and --cool are not used, so no plan reads as positive or negative.
