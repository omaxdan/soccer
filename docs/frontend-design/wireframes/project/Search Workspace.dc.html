Phase I · Search · spec

Discovery only: find an entity, then open its existing workspace. No previews, rankings, trending items or recent searches.

1 · Entry point: the Phase A SearchTrigger in the header (field on desktop, icon on tablet/mobile, "/" focuses it) opens this surface. The page underneath is dimmed, and the header is unchanged.

2–6 · Field and states: a visible label "Search PitchTerminal", 48px input, a text Clear × button, and "All" plus type chips as a secondary limiter. States: idle (one sentence) → focused (amber ring) → typing (row skeletons, query stays visible, pulse dot) → results → no results → failure. Clear restores idle without reloading.

7–13 · Groups and rows: groups show only when they have results, in type order Teams · Players · Competitions · Seasons · Venues · Countries. Within a group, rows keep the order the backend returns. Each row: TYPE tag (text) · name · one line of context. The context comes only from existing list fields:

  • Team: short name · country (teams[])
  • Player: team (players[].team, which is present in the actual list payload)
  • Competition: country when known (competition.countryCode)
  • Season: competition name (editions[])
  • Venue: city · country (venue payload; no list exists yet)
  • Country: code

14 · Disambiguation (1c): two "Bundesliga 26/27" seasons are told apart by their competition. When context is missing, the row says "No further context recorded".

15–18: no results names the query and offers Clear; failure (role=alert) keeps the query and offers Try again. Loading is announced; the result count is announced.

19–21 · Layout: desktop 680px panel 72px below the top · tablet full-width panel · mobile full-screen with Close, 44px chips and 56px rows.

22 · Accessibility: form role=search; input role=combobox with aria-controls on a listbox; groups use role=group with a count; rows are options with a spoken "type, name, context"; the arrow keys, Enter and Esc hint is shown on screen.

23 · Destinations: Team → E · Player → G · Competition / Season → D · Venue → H · Country → the existing countries/[code] route (not redesigned). Matches aren't searchable.

24 · Backend dependency: there is no unified search endpoint. The UI expects a search contract that returns typed entity results, in order, with the context fields above. Its name, parameters, matching and ordering are PENDING. The mock-up's results are hand-picked from the supplied list payloads; the product must not download and filter full lists in the browser.
