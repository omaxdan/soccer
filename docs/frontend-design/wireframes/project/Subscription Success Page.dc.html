B7 · Subscription Success · spec

VERIFIED DESIGN SYSTEM · PROPOSED UX · PENDING needs a product or backend decision

1–2 · Compositions

Desktop 1a, tablet 1b, mobile 1c. One 480px panel, centred under the progress list and top-aligned (88px from the header on desktop, 24px on mobile), so the button sits above the fold at every width.

3 · Confirmed state

  1. ✓ tile (--edge outline, 12% wash). Green appears only here, in the eyebrow and in the Status value.
  2. Eyebrow "Subscription confirmed" → h1 "Your Pro subscription is confirmed".
  3. One line: "Your account now has Pro access to PitchTerminal."
  4. Summary.
  5. Primary "Open PitchTerminal", then secondary "Back to home".

The wording says confirmed, not "active": whether a successful checkout means immediate activation is PENDING. If it does, "confirmed" can become "active" with no layout change.

4 · Summary structure

RowValueWhy it's here
PlanPro / EliteVERIFIED tier chosen in B3, carried through B6
Accountsigned-in emailVERIFIED shown in the B6 header
Status✓ Confirmed / ◌ PendingThe outcome of B6; text + glyph

Deliberately left out, rather than shown as TBD: order or subscription ID, amount, currency, billing period, renewal date, payment method, receipt and email confirmation. Adding a row later only needs one more dl line.

5–6 · Actions

  • Open PitchTerminal (primary, 48px amber) → the app entry. Proposed: Fixtures (Phase C), matching "Explore fixtures" on Landing. If the user came from a gated page, return them there PROPOSED.
  • Back to home (ghost) → Landing. No Account link: that's Phase J.

7 · Pending variant (conditional)

Shown only if the backend can report that payment succeeded but the subscription isn't confirmed yet PENDING. If it can't, this variant isn't built.

  • ◌ tile and --muted in place of green; eyebrow "Subscription · pending"; h1 "Confirming your Pro subscription".
  • Status row "◌ Pending".
  • No primary action. A dashed "Checking status" bar with the pulse-dot sits where the button goes, so the layout doesn't shift when it resolves to confirmed. Only "Back to home" is available.
  • How and when it updates, and what happens if it never confirms, is PENDING.

There's no separate "post-payment processing" variant: B6 already owns processing.

8 · Responsive

  • The panel is 480 max at every width; mobile has 12px margins and 24/20 padding.
  • Progress list stays on one line (3 short labels). The header drops the "Signed in" label on mobile.
  • Email values truncate with an ellipsis; nothing wraps under the label.

9 · Accessibility

  • The panel is role="status" with aria-live="polite", so the outcome is announced on arrival. The h1 is focusable (tabindex -1) and receives focus on load PROPOSED.
  • Success is shown by the word "confirmed" in the eyebrow, heading and Status row, plus the ✓; colour is secondary. Pending uses "pending" and ◌.
  • Summary is a dl. The progress list is an ol with aria-current="step".
  • Tab order: Open PitchTerminal → Back to home. Focus is the global 2px amber ring.
  • When pending resolves, the live region announces the new heading.
