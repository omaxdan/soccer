6 · Submitting

The button label becomes "Signing in…" with the verified pulse-dot. Fields and toggles are disabled, the form has aria-busy="true", a polite live region announces "Signing in", and the cursor shows progress. A second submit is ignored. Timeout behaviour is PENDING.

7 · Recovery entry point

"Forgot password?" is a --cool text link on the password label row, where users look for it. It leads to a recovery flow that isn't designed yet. AUTH IMPLEMENTATION PENDING: whether the flow is by email, and what it asks for.

8 · Sign-up transition

"Don't have an account? Sign up" sits under a rule at the bottom of the panel. Pricing CTAs arrive at B5 directly; this link is for visitors who reached Sign in first. Carrying a chosen plan across is PROPOSED UX for B5.

11 · Accessibility

  • Every input has a visible <label for>; there is no placeholder-only labelling.
  • autocomplete="email" and inputmode="email"; password autocomplete="current-password" so password managers work.
  • Tab order: email → forgot link → password → Show/Hide → remember → Sign in → Sign up. Enter submits from any field.
  • Show/Hide is a real button with aria-pressed and aria-controls; it doesn't clear the value.
  • Errors: aria-invalid + aria-describedby on the field; the auth error uses role="alert"; focus moves to the first invalid field on a failed client check PROPOSED.
  • Submitting: the button is disabled with aria-busy on the form and a polite status message; the label change is the visual cue, not colour.
  • Error meaning is carried by text and the "!" glyph as well as --risk. Focus uses the global 2px amber ring.
  • 44px targets throughout; mobile panel is full-width with 12px page margins; no horizontal scroll.
