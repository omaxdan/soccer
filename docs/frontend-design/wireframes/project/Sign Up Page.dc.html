B5 · Sign Up · spec

VERIFIED DESIGN SYSTEM · PROPOSED UX · AUTH IMPLEMENTATION PENDING

1–2 · Compositions

Desktop 1a works: submitting empty shows field errors, a mismatch shows the confirm error, and a valid submit shows "Creating account…" and then the success transition. Tablet 1b. Mobile 1c: full-width panel, 12px page margins, three 44px fields, no scroll on an 844px screen.

3 · Form hierarchy

  1. AuthHeader: wordmark + "← Back to PitchTerminal" (same as B4).
  2. AuthPanel: eyebrow "Sign up" (pairs with "Sign in") → h1 "Create your account" → one sentence.
  3. Form-level error banner (failure only).
  4. Email → Password (Show/Hide) → Confirm password (Show/Hide).
  5. Create account: primary, full width.
  6. Rule, then "Already have an account? Sign in" → B4.
  7. AuthFooter: Terms · Privacy · © (same as B4; no consent wording added).

Not included, as instructed: name, username, phone, country, organisation, role, marketing consent, plan, payment.

6 · Submission

The button becomes "Creating account…" with the pulse-dot and is disabled. Fields lock, the form gets aria-busy, a polite status announces progress, and a repeat submit is ignored. Same pattern as "Signing in…" in B4.

7 · Success transition

The form is replaced in place by a confirmation in the same panel: ✓ tile (--edge, text + glyph), eyebrow "Account created", h1 "Your account is ready", the email in mono, and a primary "Continue". Focus moves to the h1 and a live region announces it.

8 · Responsive

  • Desktop and tablet: 400px panel, top-aligned, padding 32; desktop offset 96px from the header, tablet 96px with 24px side margins.
  • Mobile: panel fills the width with 12px margins and padding 24/20; header 52px; all targets 44px; nothing hides. The form stays one column and the same order.

9 · Accessibility

  • Visible <label for> on all fields. autocomplete="email", and "new-password" on both password fields so managers offer to generate one.
  • Tab order: email → password → Show → confirm → Show → Create account → Sign in.
  • Errors: aria-invalid + aria-describedby to the message id; "!" glyph and text as well as --risk; focus moves to the first invalid field.
  • Failure banner role="alert"; success uses role="status" and moves focus to its heading.
  • Show/Hide are buttons with aria-pressed and aria-controls; each controls its own field.
  • Contrast follows the Phase A text tiers; the focus ring is the global amber 2px.
