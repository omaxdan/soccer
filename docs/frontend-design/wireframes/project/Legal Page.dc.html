B8 · Legal · spec

VERIFIED DESIGN SYSTEM · PROPOSED UX · PENDING legal source needed

Documents shown

Only Terms and Privacy appear, because those are the only legal destinations the approved pages already link to (every public footer, the auth footers, and the B6 billing-terms slot pointing at Terms). No legal document text, titles, dates or versions were supplied, so:

  • Titles stay "Terms" and "Privacy" as used in the footers. Final names (e.g. "Terms of Service") are PENDING.
  • Cookie, billing/subscription and refund documents aren't shown. Each can be added as another navigation item with no layout change.
  • No intro sentence under the h1, no dates, no version history.

1–3 · Compositions

  • Desktop 1a: 1152 rail; eyebrow + h1 "Legal"; 220px sticky document nav | 48px gap | article capped at 720px (about 70 characters per line at 15px).
  • Tablet 1b: nav 180px, gap 32; article fills the rest up to 720.
  • Mobile 1c: the nav becomes a 2-segment selector (44px) above the article; 12px margins. With more than 3 documents it becomes a native select PROPOSED.

4–5 · Navigation and active document

Side nav items are 40px links. The active item has a --raised fill, a --line border, weight 600, --text colour, an amber "›" marker and aria-current="page": four cues, none of them colour alone. On mobile the active segment uses the Phase A tab grammar (raised + 2px amber underline + weight). Each document has its own URL PROPOSED; the footer Legal group also marks the current document.

6–7 · Long-form reading layout

Shown in 1d as a specimen made of bars only (it contains no words, so it can't be mistaken for policy):

  • h2 document title (22/700), then the metadata line slot, which appears only for dates actually supplied.
  • Numbered sections: mono section number (--muted) + h3 heading (16/600). Sub-sections are indented 24px with n.1 numbering, but only when the source is numbered.
  • Body: Inter 15px / 1.7, --text-secondary, 16px paragraph spacing, 28px between sections, max 720px.
  • Lists keep the source's markers; defined terms use --text weight 500; links are --cool and always underlined.
  • A table of contents is added only if a document has more than about 6 sections PROPOSED.
  • Supplied text is reproduced exactly: no rewording, shortening or reordering.

9 · Footer integration

The full public footer from Landing, Features and Pricing (brand · Product · Explore · Account · Legal), with the current document marked in the Legal group. The header is the focused shell from B4–B8 ("← Back to PitchTerminal"), so the page adds no Phase C+ navigation of its own. The footer's Explore links are the ones already established on the public pages.

10 · Responsive

  • Side nav → segmented selector below 768; the article is always one column.
  • Headings wrap naturally (no nowrap); long words break inside the 720 column.
  • No horizontal overflow; all targets at least 40px (44 on mobile).
  • Type size is fixed across breakpoints (Phase A rule); only margins change.

11 · Accessibility

  • h1 "Legal" → h2 document title → h3 sections → h4 sub-sections.
  • nav aria-label="Legal documents" with aria-current on the active link; keyboard order: back link → documents → article.
  • Links inside documents are underlined as well as --cool.
  • Line length about 70 characters, line-height 1.7, contrast from the Phase A tiers (--text-secondary is 10.9:1).
  • The specimen is aria-hidden; placeholder states are real text announced via status/alert.
