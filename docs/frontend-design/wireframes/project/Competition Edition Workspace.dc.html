Data notes surfaced in UI

1iSpecification

Competition / Edition workspace · spec

Sources: competition-28.json · country-BR.json · edition-18.json · edition-18-standings.json · editions.json · globals.css. Nothing on screen is derived from outside these files.

1 · Information hierarchy

  1. Identity — country (code, alpha-3, name) → competition name → edition season label with edition switcher.
  2. Edition meta — fixture count, table as-of date, table view. Three cells, always visible in the header.
  3. Workspace tabs — Overview · Table · Fixtures.
  4. Active tab content — main column first; supporting rail second (stacks below on tablet/mobile).

Tab decision: only Overview, Table, Fixtures ship. Goals and Performance become sections inside Overview/Table once their payloads exist. Teams, Players and Venues are edition-scoped and would be tabs of this workspace, but they are hidden until a payload reports coverage present. No placeholder tabs are rendered.

2–4 · Wireframes

Desktop: 1a Overview (8/4), 1b Table full width (recommended; the table is the page), 1c Table 8/4 alternative, 1d Fixtures structure. Tablet: 1e. Mobile: 1f Overview, 1g Table. States: 1h.

7 · Token usage

  • --ink canvas + header band · --panel every .panel · --raised hover, zebra (30% mix), variant chip, mobile sub-row, skeleton bars, fixture group header · --line all borders/dividers.
  • --text names, points, meta values · --text-secondary stat cells, body copy · --muted .label-cap / .eyebrow, position · --faint breadcrumbs, zero GD, notes.
  • --amber active tab underline, focus ring, links · --edge positive GD · --risk negative GD, unavailable · --warn PAYLOAD PENDING / FUTURE markers · --cool used here only for design-time field annotations (not shipped).
  • .mono/.tnum on every number; .label-cap on column heads and panel titles; .eyebrow on the country line. Radius 4px; no shadows.

8 · Interaction states

  • Tabs: muted → hover text → active text + amber underline → focus amber outline. Route-backed (/competitions/:slug/:edition/table).
  • Standing row: odd zebra, hover --raised, whole row links to team; keyboard focus uses global amber ring. Mobile: tap toggles raised sub-row (+/−).
  • Edition switcher: dropdown of competition editions; single option renders without menu affordance being actionable.
  • VariantSelector: static with one variant; segmented with two or more; selection swaps table and AsOfLabel.
  • “Full table →” on Overview switches to Table tab.
  • Loading → skeleton per panel; error → per-panel unavailable with retry; empty → neutral copy.

9 · Responsive behavior

  • ≥1024 (lg): header meta cells right-aligned; Overview 8/4; Table full width (1b) or 8/4 (1c).
  • 768–1023 (md): meta cells wrap below identity; all 10 table columns kept, team names ellipsize; rail becomes 2-up grid under main.
  • <768: breadcrumb collapses to back link; switcher full-width 44px; meta becomes 3-cell grid; tabs scroll horizontally; table shows # · Team (shortName) · P · GD · Pts with W D L GF GA in the expandable sub-row; all targets ≥44px.

10 · Intentionally not displayed

  • Internal ids (competition 28, edition 18, team ids) and slugs as text.
  • goalDifferenceIsDerived, standingsAreObservedSnapshots and raw “present” strings.
  • Team count, matchday/round, dates, total/average goals, BTTS, form — not in any payload. Row count is not presented as a team count.
  • Qualification/relegation bands and legend.
  • Other competitions’ editions from editions.json (only used to confirm fixtureCount).
  • Country team list beyond shortName lookup; flags/crests (no image fields).

11 · Future / payload-pending

  • PAYLOAD PENDING Fixtures tab and Overview FixtureStrip — /api/v2/editions/:editionId/fixtures; grouping, filters and row fields confirmed on arrival.
  • FUTURE PRODUCT CONFIGURATION table zones (per competition config, not standings payload).
  • HOME / AWAY variants — enabled automatically when variantsPresent lists them.
  • Goals, Performance, Advanced observations — Overview/Table sections. Teams, Players, Venues — workspace tabs. All require payloads before any UI is drawn.
