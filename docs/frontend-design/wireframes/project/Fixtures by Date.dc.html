Phase C · Fixtures by Date · spec

VERIFIED payload or design system · PROPOSED · DECISION

1–3 · Layouts

Desktop 1a: 1152 rail, full width, no right rail. Tablet 1b: same grammar, narrower columns. Mobile 1c: stacked rows, 5-day strip, 44px date buttons. The page identity is always the date. Countries and competitions are sections under it, never the page title.

4 · Date navigation

  • ‹ TODAY › group (verified DateNav language) + a "Date" picker that opens the native date input. The picker is secondary.
  • Below it, a nearby-days strip (7 days on desktop and tablet, 5 on mobile) centred on the selected date; the selected day uses the Phase A tab grammar (amber underline, --text) with aria-current="date"; today carries an amber TODAY tag.
  • TODAY is highlighted (amber-dim fill) when the selected date is today; otherwise it's a plain button.
  • The strip shows no per-day counts: the endpoint is single-date, and counts for other days would need extra requests DECISION.
  • Each date is its own URL (/fixtures/YYYY-MM-DD) PROPOSED.

Header

Eyebrow FIXTURES → h1 full date from date → meta: fixtureCount ("4 fixtures") · "Times in UTC" · TODAY tag when applicable. No other metrics.

Time policy

The endpoint's day is a UTC window, so kickoffs are shown in UTC, and every row visibly belongs to the date in the h1. Showing the viewer's local time would move some fixtures across midnight DECISION. Earlier public mock-ups used BRT for illustration only.

5 · Grouping

date
└─ country (h2 · code chip + name, label-cap)          ← countries[].country
   └─ competition panel (h3 · name + seasonLabel + count) ← competitions[].name / edition.seasonLabel
      └─ fixture rows                                   ← fixtures[]

Order follows the payload. A null country renders "Country not specified" with a dashed "—" chip; its fixtures are still shown. The competition name links to Phase D, a transition only. No standings, tabs or competition stats.

8 · Score rules

  • Confirmed 0–0 renders "0 – 0" + FT (see the 4th example row).
  • COMPLETED with no result renders "—" + FT, with aria "no score".
  • Unplayed renders "–" in --faint and is never "0 – 0".
  • Half-time, extra-time values, penalties and confirmedAt are not shown in the list (Match page).

9 · Live

LIVE chip in amber with the verified pulse-dot (off under reduced-motion) and the score from the payload. No minute, events or stats; none are in the payload.

10 · Postponed / abandoned / cancelled

These stay in place on the date the endpoint returns, keeping their original kickoff time; the score slot shows "–". No replacement date is shown.

11–14 · Page states (1f)

  • Empty (real, 26 Sep): header with "0 fixtures", then a panel reading "No fixtures · There are no fixtures recorded for this date." plus a browsing hint. No reason is given.
  • Invalid date (400): h1 "Date not recognised", count "—", no strip; panel "Invalid date · The selected date is not valid." + "Go to today".
  • Loading: real header and date strip, count "Loading…"; skeleton country label → competition band → rows on the real column grid; aria-busy on main + status "Loading fixtures".
  • Failed: role="alert", "Unable to load fixtures for this date", Try again. Date navigation stays usable.

15 · Responsive

  • ≥1024: 6-column row (64 · 1fr · 88 · 1fr · 132 · 14).
  • 768–1023: the same row, narrower (52 · 1fr · 76 · 1fr · 112 · 12).
  • <768: stacked row: time + status on the left (72px), home and away on two lines, scores right-aligned; 60px rows; 5-day strip filling the width; ‹ Today › at 44px; "Date" label collapses to an icon.

16 · Accessibility

  • h1 date → h2 country → h3 competition; each country is a labelled section and rows are a ul.
  • ‹ › have aria-labels naming the target day; the strip is a nav with aria-current="date"; the date input has a label.
  • Status is always a word + glyph; winners use weight as well as colour.
  • Row links: one per row, with a full spoken summary; focus is the amber ring.
  • Loading, failed and empty states are announced via status or alert.

17 · Relationship to the shell

This is the first page on the full AppHeader (Phase A) rather than the focused auth shell, with Fixtures active. It follows the 1152 PageContainer, DataTable pattern, StatusChip grammar and Empty/Error/Loading primitives, with a compact footer (Features · Pricing · Terms · Privacy). The Phase A decision about the header nav items still applies.

Data provenance

Real: the 4 fixtures, teams, scores, statuses, kickoffs, countries, competitions and season labels of 15 Aug; the empty 26 Sep response. Structural examples (clearly bannered): the status board and the upcoming-only date.

Scope: Phase C only. No Competition, Team, Match, Player, Venue, Search or Account design.
