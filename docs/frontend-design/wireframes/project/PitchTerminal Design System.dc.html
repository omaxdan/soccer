1 · Design system summary

One dark theme. Four surfaces (ink → panel → raised → content). Inter for words, JetBrains Mono for labels and numbers. Borders frame, colour signals state, amber marks brand, focus and selection. Two table patterns, one status-chip grammar, one state grammar (cue · heading · text · action). Everything is drawn from globals.css and tailwind.config.ts; nothing new is added to the palette.

8–10 · Shells

Desktop 1g · Tablet 1h · Mobile 1i

  • ≥1024: full header (tagline, inline search); splits active (8+4, 7+5); rail beside main.
  • 640–1023: tagline + divider hidden below 640 only (VERIFIED); search becomes icon below 1024; rails drop under main as a 2-up grid at md (PROPOSED).
  • <640: header 52 + 40px scrolling nav row; search/account 44px targets; breadcrumb → back-link + current; tabs scroll with edge fade; padding stays 16; everything single column (PROPOSED). The fade is the only new visual.

11 · Navigation states

1j: anonymous, signed-in (menu open), subscribed, gated. The gate never changes the header; it appears as a locked tab plus GatedState in content, so public and app pages share one shell.

12 · Global states

1k. Empty is neutral (no action), error uses --risk for the heading only and always offers Retry, unavailable uses the verified "absent" tag, and gated uses amber because it is an access state, not a data state.

13 · Accessibility

  • Focus: 2px --amber outline, 2px offset, on every focusable element; never suppressed VERIFIED.
  • Keyboard: native links/buttons only; one tab stop per row (whole-row link); "/" focuses search; Esc closes menus and search; menu uses arrow keys, role="menu" PROPOSED.
  • Headings: one h1 per page (PageHeader); new sections use real h2/h3 rather than eyebrow paragraphs PROPOSED.
  • Landmarks: shell = header + nav(aria-label="primary"); each page owns <main>; breadcrumb nav aria-label="breadcrumb" VERIFIED.
  • Tabs: aria-current="page" on the active tab; disabled tabs are not focusable; locked tabs are focusable and announce "locked" PROPOSED.
  • Tables: native table/th, or role="table" on grid layouts VERIFIED.
  • Status: every chip has a text label and glyph; W/D/L carry the full word in aria-label; missing values read as "no value" VERIFIED.
  • Contrast: all four text tiers ≥4.5:1 on ink, panel and raised. --line is decorative; functional boundaries (inputs, selected) add amber or a text change VERIFIED.
  • Touch: 44px minimum on mobile controls PROPOSED.

14 · Reusable rules

  1. Four surfaces, in order. No panel-in-panel, no raised on canvas.
  2. Numbers are mono + tnum, right-aligned, fixed width. Missing is —, never 0.
  3. Colour never carries meaning alone: text, glyph or weight goes with it.
  4. Amber is brand, focus, active and primary action. Warn is state. Keep them apart.
  5. Border-separated tables for dense data, zebra for compact lists, never both.
  6. Tabs and chip rows scroll; they never wrap.
  7. Type scale is fixed; layout adapts.
  8. Radius is 4px everywhere.
  9. No shadows except the two verified ones; glow only on primary hover.
  10. No new colours. New needs are met with color-mix of existing tokens (15% wash, 40% border, 30/40% zebra).
